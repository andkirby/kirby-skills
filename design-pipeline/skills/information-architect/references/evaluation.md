# Evaluation

Evaluate IA by whether users can predict, find, orient, and complete primary tasks—not by whether the sitemap looks tidy.

## Static review

Check:

- intention/capability traceability
- conceptual-model consistency
- destination ownership
- sibling abstraction levels
- labeling consistency
- orphan/duplicate destinations
- global vs contextual boundaries
- cross-context workflows
- deep-link orientation
- dead ends and return paths

## Task tracing

For each primary intention, trace:

```text
entry -> orientation -> destination/context -> work -> completion -> return/resume
```

Record where users must guess, remember hidden structure, or jump contexts unnecessarily.

## Alternative comparison

When comparing IA models, use criteria that matter to the product:

- mental-model fit
- primary-task efficiency
- findability/discoverability
- context clarity
- scalability
- terminology clarity
- migration cost

Do not average arbitrary numeric scores unless the project already uses a decision model.

## Card sorting

Useful when the main uncertainty is how users naturally group or label concepts.

Do not run it merely because an IA exists.

## Tree testing

Useful when the hierarchy/labels exist but findability is uncertain. Test representative tasks against the structure without visual UI influence.

## Lightweight MVP validation

For a small product, often enough:

1. trace the top 5–10 tasks
2. review with domain users/stakeholders
3. test ambiguous labels/groups
4. revise only where evidence shows meaningful confusion

Avoid enterprise research ceremony when the decision risk is low.
